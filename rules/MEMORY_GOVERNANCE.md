# Agent Context Memory Governance Rules (표준 거버넌스 규격)

> 본 문서는 3계층 인지 메모리 시스템(Three-Tier Memory Model)의 런타임 표준 가드레일 규격입니다.

> [!CAUTION]
> **규칙 작성 및 템플릿 수정 가드레일 (Strict Guardrails)**:
> 1. **문서 역할 격리**: 본 문서는 **ACM 시스템 자체의 인지 메모리 표준 거버넌스 규격 전용**입니다. 프로젝트 일반 개발/비즈니스 규칙은 본 파일이 아닌 루트의 `AGENTS.md` 내 `# Project Execution Rules` 하위에 작성해야 합니다.
> 2. **템플릿 수정 엄격 금지**: 본 파일 등 프로젝트 규칙 수정 시 `acm-template/` 하위 파일(규칙/스크립트/설정 등)을 연쇄 수정하는 행위를 엄격히 금지합니다. `acm-template/`는 타 프로젝트 배포용 원형 자산이며, 사용자의 명시적 요청이 있을 때만 수정합니다.

---

## 1. 3대 정본 및 고유 식별자 규격
1. **작업 기억 (L1)**: `.agents/task/task.md`
   - 단일 활성 작업 정본 (Single Source of Truth), 상시 **5KB 이하** 유지.
   - 식별자: `TSK-{자연수}` (패딩 없음, 예: `TSK-1`, `TSK-24`). 신규 발급 시 전체(완료 포함) `최대 번호 + 1`.
   - 서식 지원: 블록형(`### TSK-X. 작업명` 하위 `- **상태**: [상태]`) 또는 불릿형(`- [상태] **TSK-X. 작업명**`).
2. **장기 지식 (L2)**: `.agents/memory/patterns-index.md` / `patterns/`
   - 패턴 식별자: `P-{순차증가번호}` (예: `P-01`, `P-45`).
   - `patterns/` 하위에 개별 샤딩 파일로 보관하며, `patterns-index.md`에는 1행 요약 메타데이터만 등록.
3. **거시 ADR 로그 (L2)**: `.agents/memory/project-changelog.md`
   - 아키텍처 식별자: `LOG-{순차증가번호}` (최상단 누적 Prepend).
4. **콜드 아카이브 (L3)**: `.agents/task/task-completed.md`
   - Git 커밋 SHA 해시(Git 환경) 또는 사용자 승인 완료 표기(비-Git 환경)를 확보한 완료 태스크 영구 보관소.

---

## 2. 작업 수명주기 및 Git 원자 커밋 거버넌스
1. **상태 라이프사이클**: `[ ]` (대기) -> `[진행 중]` -> `[커밋 대기]` (검증 완료) -> `[x]` (커밋 완료).
2. **완료 이관 원칙 및 무결성 게이트**:
   - **Git 환경**: 실제 Git 커밋 SHA 획득 전 `task.md`에서 `task-completed.md`로 조기 이관 엄격 금지 (이관 시 커밋 해시 필수 명기: `(Commit: abc1234)`).
   - **비-Git 환경**: 사용자의 수동 이관을 전면 허용하며, 에이전트가 작업을 완료했을 때는 임의로 조기 이관하지 않고 반드시 사용자에게 검증 결과 보고와 함께 완료 이관 여부를 확인(승인)받은 후 `(Completed: YYYY-MM-DD / Non-Git)` 표기로 이관.
3. **일괄 커밋 금지 및 스크립트 강제**:
   - `git add .` 일괄 스테이징 절대 금지.
   - 반드시 `node scripts/group-status.cjs`를 구동하여 정본 범위별로 분할 원자 커밋 수행.

---

## 3. 0토큰 온디맨드 검색 원칙 (Just-In-Time Grep)
1. **전수 통조회 100% 금지**: 세션 시작 시 `patterns/` 하위 파일이나 전체 히스토리 문서를 통째로 읽는 행위 엄격 금지.
2. **색인표 정밀 Grep**: 작업 키워드로 `patterns-index.md` 요약열만 `grep_search`하고, 매칭된 특정 샤딩 파일(`patterns/P-XX-*.md`)만 핀포인트 로딩 (미매칭 시 즉시 종료).
3. **바이패스 프리픽스**: 사용자 프롬프트에 `/스킵`, `/태스크` 프리픽스가 있거나 단순 질의 시 지식 검색 생략.
4. **사후 증류**: 검증 완료된 범용 재사용 솔루션에 한해 `P-XX` 샤딩 파일 신설 및 `patterns-index.md` 1행 등록.

---

## 4. 거시 아키텍처 ADR 조건부 열람 원칙
1. **평소 조회 금지**: 통상 작업 시 `project-changelog.md`를 조회하지 않음 (0토큰 유지).
2. **3대 조건부 이벤트에 한해 제한적 슬라이스 조회**:
   - 1) 전역 인프라/설정 수정
   - 2) 회귀 결함 역추적
   - 3) 원격 대규모 머지 직후
   - 위 조건 발생 시에만 최상단 1~2개 블록(40라인 이내)만 슬라이스 조회.

---

## 5. 멀티 에이전트 동시성 및 작업 영역 격리 거버넌스
1. **작업 배타적 점유**: 복수 에이전트 환경에서 태스크 착수 시 담당자 명기(`- **상태**: [진행 중 (Agent: ID)]`), 타 에이전트가 진행 중인 태스크 간섭 금지.
2. **대상 영역 상호 배타성 (Path Isolation)**: 병렬 실행 태스크 간 `대상 영역(Target Paths)` 파일 경로 중첩 엄격 금지 (공통 파일 수정 필요 시 직렬 수행).
3. **식별자 원자 발급**: `TSK-X`, `P-XX`, `LOG-XX` 발급 전 정본 실시간 확인 후 `최대 번호 + 1` 확정.
4. **Git 조작 직렬화**: `.git/index.lock` 충돌 차단을 위해 스테이징 및 커밋 조작은 직렬 수행.

---

## 6. 브랜치 전략 및 배포 아티팩트 격리 거버넌스
1. **정본 소스 브랜치 (`master` / `develop`)**:
   - 단위/E2E 테스트, 문서, 거버넌스 메모리(`.agents/`)를 포함한 프로젝트의 전체 소스 코드를 온전히 관리하는 최상위 단일 정본.
2. **배포 전용 브랜치 (`dist`)**:
   - `package.json`의 `files` 화이트리스트에 명시된 npm 패키지 배포 대상 파일만 격리 유지.
   - `dist` 브랜치에 대한 직접 개발 또는 수동 `git merge`는 엄격히 금지하며, 반드시 `npm run dist:sync` 엔진 또는 GitHub Actions(`.github/workflows/release-dist.yml`) 파이프라인을 통해서만 배포 커밋을 일방향 반영.

---

## 7. 규칙 작성 영역 및 배포 템플릿 격리 거버넌스
1. **규칙 분리 원칙**:
   - `rules/MEMORY_GOVERNANCE.md`: ACM 인지 메모리 3계층 아키텍처 및 시스템 가드레일만 관리.
   - 루트 `AGENTS.md`: 프로젝트 고유 비즈니스 로직, 코딩 컨벤션, 프로젝트 실행 규칙 관리.
2. **배포 템플릿 불변 원칙 (`acm-template/`)**:
   - `acm-template/` 디렉터리는 타 프로젝트로의 초기 배포/설치를 위한 원형(Template) 자산임.
   - 프로젝트 내 파일 수정 시 `acm-template/` 내부 파일을 함께 수정해서는 안 되며, 사용자의 명시적인 "템플릿 수정/업데이트" 지시가 있는 경우에만 한정적으로 수정.
