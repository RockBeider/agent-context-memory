# [P-02] 작업 단위(Task-Centric) 원자적 커밋 거버넌스 및 자동 분류

- **식별자**: P-02
- **분류**: 형상 관리 거버넌스
- **등록일**: 2026-10-19
- **관련 파일**: `scripts/group-status.cjs`, `.agents/task/task.md`

---

## 1. 증상 (Symptom)
- 여러 기능 개발이나 리팩토링이 동시에 진행될 때 `git add .` 일괄 커밋으로 인해 무관한 수정사항들이 하나의 커밋에 뒤섞여 롤백이 불가능해지고 히스토리 추적성이 상실됨.

## 2. 원인 (Root Cause)
- 작업 단위(Task)에 대한 명시적 경계(Scope) 관리 없이, 빌드가 성공하면 모든 변경 파일을 한 번에 스테이징하는 비구조적 워크플로우.

## 3. 해결책 (Solution)
- `task.md`에 명시된 활성 태스크의 **대상 영역(Target Scope)**을 파싱하여, Git 변경 파일들을 작업 단위별로 분할하는 커밋 자동화 도구(`scripts/group-status.cjs`)를 사용.
- 커밋 메시지 접두사에 `[TSK-X]` 태그를 의무적으로 부여하여 태스크와 Git 커밋 해시를 1:1로 결속.

```bash
# 특정 작업 번호(TSK-1)의 변경 파일만 독립 스테이징 및 커밋
node scripts/group-status.cjs --commit=1
```

## 4. 검증 및 회귀 방지
- 단일 PR/브랜치에서 5개 이상의 파일이 변경되더라도 개별 커밋 단위로 깨끗하게 분할되어 반영됨을 확인.
