# Project Changelog & Architecture Decision Records (ADR)

> [!IMPORTANT]
> **0토큰 온디맨드 및 색인표 우선 조회 원칙**:
> 1. 본 문서는 거시 아키텍처 결정 사항(ADR) 및 시스템 주요 변경만 누적 기록합니다.
> 2. 신규 결정 사항은 `LOG-XXXXXX`(`acm adr add` / `acm id adr` / MCP)를 발급하여 **1) 상단 `ADR Index Map` 표 최상단(샘플 위)에 1행 추가**, **2) 하단 `ADR 상세 기록` 최상단에 상세 블록 추가**를 동시 수행합니다 (`LOG-00`은 양식 샘플입니다).
> 3. AI 에이전트는 평소 본 파일을 전수 조회하지 않으며, 3대 조건부 이벤트(공통 모듈 변경, 대규모 머지, 설정 수정) 시 **상단 색인표(1~35행)만 먼저 열람하거나 키워드로 `grep_search`한 뒤 필요한 `[LOG-*]` 섹션만 핀포인트 조회**합니다.

## 2. ADR 상세 기록 (Architecture Decision Details)

### [LOG-00] [YYYY-MM-DD] (양식 샘플 - 실제 ADR 아님) 아키텍처 결정 제목

- **관련 커밋/브랜치**: (예: `init / main` 또는 `TSK-K7M29A`)
- **결정 배경 및 목적**:
  - (예: 시스템 전역 설정 변경 또는 코어 아키텍처 도입 배경 기술)
- **아키텍처 결정 사항**:
  - (예: 결정된 핵심 구조, 디렉터리 정책, 상태 관리 원칙 등 기술)
- **예상 효과**:
  - (예: 유지보수성 향상, 토큰 절감, 성능 개선 등 기대 효과 기술)
