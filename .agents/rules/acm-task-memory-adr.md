## 1. Post-Task Knowledge Distillation (.agents/acm/memory/patterns/)
- For confirmed reusable solutions only, create an immutable sharded file (`.agents/acm/memory/patterns/P-XXXXXX-*.md`, issued via `acm` / `npm run acm --` / `node scripts/acm/acm-db-cli.cjs` `pattern add` / `id pattern` or MCP; `P-00` is a format sample and legacy `P-XX` files remain valid) using the 5-line compact format (`**Date**:`, `**Category**:`, `**Symptom & Root Cause**:`, `**Solution Pattern**:`, `**Related Files**:`) and append 1 summary row to `patterns-index.md`.
- In `sqlite` mode (`.agents/acm/config.json`, `markdownProjection: false` by default), record and query patterns solely via `acm` / `npm run acm --` / `node scripts/acm/acm-db-cli.cjs` (`pattern add`, `search`) or MCP tools (`acm_pattern_save`, `acm_pattern_get`, `acm_search`) with `supersedes` version chaining—do not write Markdown pattern files manually.

## 2. Macro Architecture Decision Records (.agents/acm/memory/project-changelog.md)
- **Reading**: Only on 3 conditional events (1. global infrastructure/config changes, 2. regression tracing, 3. immediately after large remote merges), slice-read the top `ADR Index Map` (`StartLine: 1, EndLine: 35`) or `grep_search` by keyword to pinpoint `LOG-*`, then read only that detail block. In `sqlite` mode, use `npm run acm -- adr list` / `npm run acm -- search --kind=adr` (or `acm` / `node scripts/acm/acm-db-cli.cjs`) or `acm_search`.
- **Writing**: Only on macro architectural changes (ADRs), prepend 1 summary row to `ADR Index Map` and prepend a detail block (`### [LOG-XXXXXX] [YYYY-MM-DD] Title`, issuing `LOG-XXXXXX` via `acm` / `npm run acm --` / `node scripts/acm/acm-db-cli.cjs` `adr add` / `id adr` or MCP; `LOG-00` is a format sample only) at the top of the detail section. Never log routine feature work or minor bug fixes here; keep those in the `task` tier. In `sqlite` mode, record solely via `adr add` CLI or `acm_adr_add` without editing Markdown files manually.
